BIOLOGICAL COMPUTATIONAL DETAILS AND REPRODUCTION

Paths below are relative to workflows/biological/ unless explicitly stated.
Run tasks through the repository-level tools/reproduce.py to keep reference
files intact. docs/REPRODUCTION.md defines the supported task names, execution
workspace and required dependencies. workflows/scc/ is a separate workflow
with its own model-input schema and finite checks.

biological_extended_details.tex supplies conventions, source qualifications,
methods, witnesses, scope and bibliographic credits. These reference files are
not standalone PDF builds. Table labels and descriptive section headings are
their locators. Mathematical notation and numerical table contents are retained.

Search budgets and scope of proof
--------------------------------
Original selected-target searches use 120 analysis seconds, residual size 18,
at most six additional pins and 30,000,000 reserved work units. A unit is an
original residual successor evaluation or compatible residual state in a
candidate classification; the whole candidate state count is reserved before
evaluation. Parsing, discovery and support work are separate. Local rule
compilation covers 3176 CD4 and 3780 macrophage corners, maximum physical arity 10.
Every smaller pin cardinality is excluded before declaring an optimum; all
minimum sets require the successful cardinality to finish. The APC original
run checked 2424 candidates and reserved 29,999,104 units, after excluding all
834 smaller sets. The next candidate exceeded its cap. Empty support/cyclic
discovery legitimately gives zero candidate count without zero analysis work.

The later fixed-point enumeration allows 24 free coordinates in chunks of 8192.
SCC optimization has size/pin caps 18 and 10^8 work units per complex component,
with one local-row evaluation or controlled successor-edge traversal per unit.
Enumeration of all minimizers and restricted eligible sets has a separate
component cap 12. None of these guards is exhausted in the reported study.
The two work definitions are not interchangeable, and neither set of caps
is a tractability claim for arbitrary models. A cap stop retains bounds and
status; it is not a claim of infeasibility.

Reproduce current all-target and fair-update records
----------------------------------------------------
From an isolated biological workflow copy, choose a new output directory:
  python src/run_all_targets.py --output new_all_target_results
  python verification/verify_all_targets.py --production new_all_target_results/all_targets.json --output new_all_target_results/independent_biological_validation.json
  python verification/async_memory_check.py --output new_all_target_results/async_memory_check.json
The production runner needs Python 3.10+ and NumPy. The two independent
verifiers use the standard library. The asynchronous check retains selected
OFF/APC targets and exact 3/4 costs, not an asynchronous random-ensemble law.
Its four graphs have 64/192 and 8192/51200 states/state-changing edges.
The main proof gives convergence under coordinate fairness, with no uniform
update-count bound for unbounded delays. A unique terminal SCC alone is not
the certificate; the whole state-changing graph must satisfy the stated test.
Read README.txt, README_Biological.txt and verification/README.txt for complete options.

Reproduce the original smaller and selected-target studies
---------------------------------------------------------
From the Biological root, use a fresh absolute output directory for the small maps:
  python biological/src/reproduce.py --output /absolute/path/to/new_small_results
Run the inexpensive original larger-model implementation checks with:
  python larger_networks/src/test_runner.py
To rerun the original larger searches explicitly in a new directory:
  python larger_networks/src/benchmark.py --protocol larger_networks/protocol/contexts.json --output /absolute/path/to/new_large_results
To verify those new results independently:
  python larger_networks/verification/verify_results.py --protocol larger_networks/protocol/contexts.json --results /absolute/path/to/new_large_results --output /absolute/path/to/new_large_results/independent_results.json
To audit the preserved original results instead, use --results
larger_networks/results with a separate output location. The original full
searches are not required to reproduce the current SCC-based all-target
extension. Runtime and memory can vary; an earlier wall cutoff can limit
progress without invalidating retained bounds. Original README files give
the remaining dependencies and exact operation details.

Separate SCC solver workflow
---------------------------
From an isolated copy of workflows/scc/:
  python scc_control.py example_network.json -o example_result.json
  python verification/validate_scc_solver.py --output results/solver_validation.json
Use workflows/scc/README.txt and workflows/scc/verification/README.txt. It uses Python 3.10+
and the standard library. It is a general synchronous permanent-pinning
solver/validation package, not a replacement for the Biological model protocols or
the random-network study reproduction. Its declared finite guards and
support/graph conventions remain as documented in the SCC workflow.
